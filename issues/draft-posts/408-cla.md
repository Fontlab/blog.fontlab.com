## Roboto Flex and the thirteen axes

---
title: Roboto Flex and the thirteen axes
slug: roboto-flex-thirteen-axes
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - OpenType
  - variable fonts
summary: The most ambitious open‑source variable font Google has shipped, and what it tells you about where parametric design is heading.
---

Christian Robertson drew Roboto in 2011 for Android and shipped what was, by phone‑era standards, a complete family. Ten years later, David Berlow's Font Bureau team — Santiago Orozco, Irene Vlachou, Ilya Ruderman, Yury Ostromentsky, Mikhail Strukov — turned it into Roboto Flex, a parametric system with **thirteen axes**: five standard (`wght`, `wdth`, `opsz`, `GRAD`, `slnt`) and eight parametric (`XTRA`, `XOPQ`, `YOPQ`, `YTLC`, `YTUC`, `YTAS`, `YTDE`, `YTFI`). Released September 2021, current version 3.200 (2023). The architecture is inherited from Amstelvar (2017), the experimental sibling that pioneered the parametric idea.

Eight parametric axes is a lot to ask of a designer. So Type Network built `typeroof` and `videoproof` to prove that the design space actually works — that a thirteen‑dimensional sliding panel produces text the eye accepts at every step.

> "Roboto Flex upgrades Roboto so it becomes a more powerful typeface system. With Flex, you can customize Roboto to express and finesse your text in ways never before possible." — Type Network

The lesson for FontLab 8 users isn't "design thirteen axes." It's that variable fonts have stopped being an experiment. The toolchain — designspace, mastering, validation — is good enough that one team can ship something this large and have it work in browsers shipped today.

## fvar, avar, HVAR — the tables that hold a variable font together

---
title: fvar, avar, HVAR — the tables that hold a variable font together
slug: fvar-avar-hvar-variable-font-tables
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - OpenType
  - variable fonts
summary: A variable font is a static OpenType file plus a small stack of new tables. Once you know what each one does, the format stops being magic.
---

The thing nobody tells you when they say "variable font" is that it isn't a new file format. It's an OpenType file with a few extra tables nailed on:

- **fvar** — the axes the font has, plus named instances ("Bold", "Condensed Italic")
- **gvar** (TrueType outlines) or **CFF2** (PostScript outlines) — the deltas, the per‑axis offsets that move points
- **avar** — non‑linear axis remapping, so a slider midpoint doesn't have to be a visual midpoint
- **HVAR** — per‑instance advance‑width deltas, so layout engines don't have to interpolate metrics
- **MVAR** — font‑wide metric variations (cap height, x‑height, line gap)
- **STAT** — style attributes, what makes a "Bold Condensed" findable

Joint announcement, ATypI Warsaw, September 2016 — Adobe, Apple, Google, Microsoft on the same stage. John Hudson's introduction on Medium that month is still the readable single source. Wolfgang Beinert's German *Typolexikon* essay is the contrarian counter‑read worth airing for balance.

The reason this matters for FontLab 8 is mundane: when something doesn't render right in Safari but does in Chrome, the answer is almost always one of these tables disagreeing with another. Knowing what each one is for shortens the bug hunt from a day to twenty minutes.

- https://learn.microsoft.com/en-us/typography/opentype/spec/otvaroverview
- https://medium.com/variable-fonts/https-medium-com-tiro-introducing-opentype-variable-fonts-12ba6cd2369
- https://www.typolexikon.de/variable-fonts/
- https://googlefonts.github.io/gf-guide/variable.html

## Optical sizing's lost century

---
title: Optical sizing's lost century
slug: optical-sizing-lost-century
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - typography
  - variable fonts
summary: Caslon's 1720 broadsheet showed every size as a separately cut punch. Phototype erased the idea. The opsz axis, finally, brings it back.
---

Open William Caslon's 1720 specimen and you see something digital type spent a century unlearning: every size of every face is a different drawing. Six‑point isn't a shrunken twelve‑point — it's a thicker, wider, more open thing, cut by a different punch. Phototype killed it (one master, photographed up and down). Digital didn't bring it back.

Variable fonts did. The `opsz` axis tells the renderer the intended size, and the font swaps in shapes drawn for that size — heavier strokes and looser spacing at six point, finer strokes and tighter spacing at sixty. Amstelvar (2017, 8–144 pt) and Roboto Flex pioneered the continuous version. Adobe's Source Serif 4 (January 2021) shipped five *discrete* opsz styles instead — Frank Grießhammer's editorial choice, on the grounds that five carefully drawn sizes beat infinite mediocre ones.

There's an unresolved fight over what `opsz` units actually mean — physical points or CSS pixels — that has lived as GitHub issue roboto‑flex#104 for years (Twardoch, Penney, Hudson, Crossland). The answer matters more than it sounds. CSS `font-optical-sizing: auto` is the default in most browsers, and "auto" is doing slightly different things on each platform.

![Caslon 1720 specimen showing every size cut as a separate punch](https://upload.wikimedia.org/wikipedia/commons/9/93/Caslon-schriftmusterblatt.jpeg)

## Animating font‑variation‑settings on the web

---
title: Animating font‑variation‑settings on the web
slug: animating-font-variation-settings
date: 2026-05-08
authors:
  - editorial
categories:
  - variable fonts
  - web
  - typography
summary: A heading that thickens on hover, a paragraph that narrows on scroll. No SVG, no canvas, no JS — just CSS and one font file.
---

Browser support for `font-variation-settings` has been broad since September 2018. Animating the value works the way other CSS animation works:

```css
@keyframes breathe {
  from { font-variation-settings: "wght" 200; }
  to   { font-variation-settings: "wght" 800; }
}
h1 { animation: breathe 4s ease-in-out infinite; }
```

That's the easy version. The honest version is that animating a variable font hits the GPU harder than people expect — every frame, the renderer has to interpolate outlines and rerasterise. Mandy Michael's recommendation, which has aged well, is to wrap animated text in an `IntersectionObserver` and pause animation when the element scrolls offscreen. On a long page with twenty animated headings, the difference is the laptop fan.

Two milestones worth keeping in mind. Nick Sherman launched **v‑fonts.com** at Robothon in March 2018 — still the best gallery for what's out there. Laurence Penney's **Axis‑Praxis** dates from late 2016, before the spec was even finished, and remains the deepest playground. Dinamo's "Using Variable Fonts on the Web" guide is the long read.

The mistake people make is treating the slider as a feature to demo. It isn't. The interesting work is the slider you don't see — opsz drifting with viewport, weight tightening at small sizes, GRAD nudging on dark mode. Animation that reveals the system is worth doing. Animation that performs the system is a screensaver.

## The four‑format colour‑font story (update)

---
title: The four‑format colour‑font story, ten years on
slug: colour-font-formats-update
date: 2026-05-08
authors:
  - editorial
categories:
  - colour fonts
  - OpenType
  - FontLab 8
  - TransType 4
summary: Apple SBIX, Google CBDT, Microsoft COLR, Adobe/Mozilla SVG‑in‑OT. COLRv1 won most browsers — but OT‑SVG didn't actually die.
---

Four formats, four vendors, one underlying problem: emoji didn't fit OpenType's monochrome assumptions. Apple shipped **SBIX** (PNG bitmaps). Google shipped **CBDT/CBLC** (also PNG bitmaps, with size tables). Microsoft and Adobe pushed two opposite vector approaches: **COLR** (layered glyphs with a palette) and **SVG‑in‑OpenType** (full SVG embedded in the font). For a while in the late 2010s it looked like SVG would win — Photoshop CC 2017 shipped with Trajan Color Concept, the first OT‑SVG release; Type With Pride's Gilbert (April 2017) took it mainstream as a tribute to Gilbert Baker.

Then COLRv1 — Google + Microsoft, OpenType 1.9, 2021 — added gradients, blend modes, and a paint‑tree model that matched what designers actually wanted. Chrome 98 shipped February 2022 (Dominik Röttsches). Edge followed via Chromium. Firefox 107 in November 2022. Safari arrived for Interop 2025. The size argument was decisive: full Noto Emoji as CBDT is **9 MB**; the same set as COLRv1 + WOFF2 is **1.85 MB** — about a fivefold reduction.

The thing the original "COLRv1 won" headline got wrong is that **OT‑SVG didn't actually die.** Safari still renders it. Adobe still authors with it. So we have a split: COLRv1 across Chromium and Firefox, OT‑SVG across Safari and Adobe's apps. One‑format‑fits‑all is still aspirational.

> "I used to say the OpenType‑SVG format was the best… until I realized this is just too complex for a low‑level job like text rendering. … So I switched sides to COLR." — Roel Nieskens

For TransType 4 the practical implication is unglamorous: round‑tripping a colour font means knowing which target the user actually has. SBIX in, COLRv1 out is fine for a web team. SBIX in, SVG out is what an Adobe shop probably needs.

- https://blog.typekit.com/2013/10/08/svg-opentype-genesis/

## CPAL palettes and CSS font‑palette

---
title: CPAL palettes and CSS font‑palette
slug: cpal-font-palette
date: 2026-05-08
authors:
  - editorial
categories:
  - colour fonts
  - web
  - FontLab 8
summary: A colour font with one palette is a coloured drawing. A colour font with thirty palettes is a theme system.
---

CPAL is the OpenType table that holds the palettes a COLR font uses. Each palette is a list of colours, indexed; index `0xFFFF` is reserved to mean "the foreground colour" — i.e. inherit `color` from CSS. That tiny convention is why you can drop a colour font into dark mode and the parts that should follow text colour just do.

On the web side, `@font-palette-values` lets a designer override or remix the palettes the font ships with:

```css
@font-palette-values --night {
  font-family: "Bradley Initials";
  base-palette: 2;
  override-colors: 0 #f0c, 1 #14213d;
}
.heading { font-palette: --night; }
```

Underware's Plakato Color Grade ships **1,360 palette entries** in CPAL — enough that you can change the entire feel of the font without touching its outlines. WebKit's "Customizing Color Fonts on the Web" demo, built on DJR's Bradley Initials, is still the cleanest live example.

The mental shift to make is that a colour font isn't *a coloured drawing*. It's a black‑and‑white machine that gets coloured in by CSS. Once you see it that way, the design problem becomes "what palettes ship by default" — the same problem stylesheets have always had.

## Emoji is older than you think

---
title: Emoji is older than you think
slug: emoji-older-than-you-think
date: 2026-05-08
authors:
  - editorial
categories:
  - colour fonts
  - emoji
  - history
summary: It wasn't NTT Docomo in 1999. SoftBank — then J‑Phone — shipped 90 emoji on the SkyWalker DP‑211SW in 1997. Including the pile of poo.
---

The story everyone tells is that Shigetaka Kurita designed emoji at NTT Docomo in 1999. It's a good story; it's also wrong, and Emojipedia corrected the record in 2019. The first commercial emoji set shipped on the **SoftBank/J‑Phone SkyWalker DP‑211SW in 1997** — ninety glyphs, monochrome, twelve by twelve pixels. The pile of poo was already there.

Apple Color Emoji shipped on **November 21, 2008** with iPhone OS 2.2 — 471 glyphs, originally Japan‑only via SoftBank's exclusivity deal, designed by Raymond Sepulveda, Angela Guzman, and Ollie Wagner. Two years later Unicode 6.0 (2010) accepted them as proper code points. Microsoft open‑sourced 1,538 Fluent Emoji on **August 10, 2022** under MIT — the first major vendor to make their emoji actually freely reusable.

The Apple set still has its easter eggs hiding in plain sight. The 📰 newspaper headline reads "The Apple Times". The 📅 calendar shows **July 17** — the day Apple announced iCal in 2002, and the day Emojipedia eventually claimed as World Emoji Day.

The reason this matters for a font tool is that emoji set the social precedent for COLRv1, OT‑SVG, and CPAL. Every "should fonts have colour" argument from the 2000s lost the moment a Japanese teenager could send a smiley.

## From Multiple Master to OpenType variable fonts

---
title: From Multiple Master to OpenType variable fonts
slug: multiple-master-to-variable
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - OpenType
  - variable fonts
  - history
summary: Adobe's MM. Apple's TrueType GX. Both worked. Both lost. Twenty‑five years later the same idea won, and FontLab was in the room.
---

Adobe announced **Multiple Master** in 1991. Myriad MM had four masters — light/black × condensed/extended — and let you generate any instance between. Minion MM added an optical‑size axis (Caption to Display). It was, technically, beautiful. Commercially it died slowly. Tamye Riggs's *Adobe Originals Silver Anniversary* essay puts it best: "Users were forced to generate instances for each variation of a font they wanted to try, resulting in a hard drive littered with font files bearing such arcane names as `MinioMM_578 BD 465 CN 11 OP`." Last MM release: 1999.

Apple shipped its own answer the same year, inside QuickDraw GX — **TrueType GX Variations**. Same idea, different table layout. It worked. It also lost, mostly because GX as a whole lost.

Then nothing, for sixteen years. Then ATypI Warsaw, September 2016: Adobe, Apple, Google, and Microsoft jointly announce OpenType 1.8 with variations. The mechanism is essentially TrueType GX with the lessons of MM applied — and FontLab Ltd was inside the working group, pushing for it, and shipped support in **FontLab VI** when it landed. David Lemon was at Adobe through both eras. The continuity is unusual: most format wars don't have the same people on both ends.

The takeaway for a designer working in FontLab 8 today is that variable fonts are not new. They are the third attempt at the same idea, by mostly the same engineers, after twenty‑five years of finding out what didn't work.

## WOFF and the Emmy nobody expected

---
title: WOFF, WOFF2, and the Emmy nobody expected
slug: woff-woff2-emmy
date: 2026-05-08
authors:
  - editorial
categories:
  - web
  - OpenType
  - history
summary: Three Robofab people, one Mozilla engineer, one Google compression team, and a Technology & Engineering Emmy in 2021.
---

The Web Open Font Format started in 2009 as a draft with three names attached: **Jonathan Kew** (Mozilla), **Tal Leming**, and **Erik van Blokland**. Submitted to the W3C in April 2010, recommendation status by December 2012. The mechanism was modest — a thin wrapper around an OpenType file with metadata and zlib compression — but the politics were huge. Foundries had refused to license desktop fonts for raw `.otf` web embedding for years. WOFF was the format they would license.

WOFF2 followed in April 2012. The compression was Google's **Brotli** — Jyrki Alakuijala and Zoltán Szabadka — and the wrong‑footing detail is that Brotli was developed *for fonts first*, before becoming the general‑purpose web compression you now know it as. RFC 7932 in July 2016 standardised the algorithm for everything else. WOFF2 vs WOFF: **roughly 30% smaller on average** across the Google Fonts corpus, **over 50% smaller for CJK**. W3C Recommendation, March 2018.

In 2021 the Television Academy gave the W3C a **Technology & Engineering Emmy** for font standardisation. The recipients included the WOFF working group, Google, and the **CEO of FontLab Ltd** — one of the few times a font tool company has won a piece of broadcast hardware named after a 1940s televised play.

The lesson is not that WOFF was hard. It's that the parties who had to agree — Mozilla, Adobe, Microsoft, Apple, Google, every type foundry that mattered, and the W3C — had no business agreeing on anything, and somehow did. The format works because the people behind it had spent twenty years arguing about everything else.

- https://w3c.github.io/woff/woff2/
- https://github.com/google/woff2

## Halftone, from Fox Talbot to *A Scene in Shantytown*

---
title: Halftone, from Fox Talbot to *A Scene in Shantytown*
slug: halftone-shantytown
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - history
  - print
summary: The trick that made photography printable in newspapers was a screen of dots, and it took thirty years to invent.
---

William Henry Fox Talbot floated the idea of "photographic veils" in the early 1850s — a fine mesh laid over a photographic plate to break a continuous tone into something a printing press could hold. It took another generation to make it work. **Stephen H. Horgan** ran the first newspaper photograph (Steinway Hall) in the *New York Daily Graphic* on **December 2, 1873**, and the first full‑tone halftone, *A Scene in Shantytown, New York*, on **March 4, 1880**. **Frederic Ives** patented the commercially viable method in 1881. **Georg Meisenbach's** "Autotypie" followed in Munich in 1882.

The numbers that mattered for the next century: newspapers ran around **85 lines per inch**, magazines **133–150 lpi**, fine art catalogues higher. CMYK colour process layered four screens at carefully chosen angles — typically 15°, 45°, 75°, 0° — so the dots wouldn't moiré against each other. Get the angles wrong and the page gets a rosette pattern that nobody asked for.

![*A Scene in Shantytown, New York*, the first full‑tone newspaper halftone in the US, March 4, 1880](https://upload.wikimedia.org/wikipedia/commons/9/93/A_Scene_in_Shantytown%2C_New_York_%281880%29.png)

For Vexy Lines this is foundational. Halftone is a way of representing continuous tone with discrete marks — exactly the problem a vector tool solves on the modern side. The 1880 broadsheet and a 2026 SVG export are the same algorithm with different output devices.

## Dithering, ditherpunk, and Bill Atkinson

---
title: Dithering, ditherpunk, and Bill Atkinson
slug: dithering-ditherpunk-atkinson
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - history
  - graphics
summary: From Larry Roberts at MIT to *Return of the Obra Dinn*, sixty years of pretending a one‑bit display has greys.
---

The lineage is short and famous if you know where to look. **Larry Roberts** at MIT, 1961 — the first paper on adding noise to grayscale to fool the eye into seeing more tones than the device has. **Bryce Bayer** at Kodak, 1973 — the recursive matrix dither still named after him. **Floyd–Steinberg**, 1976 — error diffusion with the canonical 7/16, 3/16, 5/16, 1/16 weights, the algorithm that made laser printers possible. **Bill Atkinson** at Apple, 1983–84 — a variant for the original Macintosh's one‑bit display that **discards 25% of the error** at each pixel. The discard sounds wrong; in practice it produces sharper, higher‑contrast images on cheap screens, which is what MacPaint and HyperCard needed. Atkinson died on June 5, 2025, of pancreatic cancer.

> "[Atkinson] was fascinated by the concept of dithering, by which computers using dots could create nearly photographic images similar to the way newspapers printed photos." — AppleInsider obituary

After Atkinson it gets quieter and weirder. **Mark Ferrari** drew dithered EGA backgrounds for LucasArts (Zak McKracken, Loom, Monkey Island) and pioneered colour cycling — animation by rotating the palette instead of redrawing. **Lucas Pope's *Return of the Obra Dinn*** (2018) is the thing that made the genre legible to a generation that hadn't lived through 1‑bit displays. **Surma's** 2021 essay ("Ditherpunk") gave the style its name.

The reason this lineage is worth remembering when working in Vexy Lines: dithering is the original argument that *line is enough*. You don't need tone, you don't need colour, you need a pattern of marks placed precisely. Every modern halftone, hatching, and stipple effect descends from somebody at MIT in 1961 deciding the eye can be fooled.

- http://www.effectgames.com/effect/article-Q_A_with_Mark_J_Ferrari.html

## The FontLab book in Korean

---
title: The FontLab book in Korean
slug: fontlab-book-korean
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - Hangul
  - books
summary: April 2025 — Kwon Gun‑oh published 폰트랩 타입 디자인, the first Korean‑language guide to making Hangul fonts in FontLab.
---

Most font editors grew up around Latin. The grid is alphabetic, the tools assume baseline‑and‑x‑height, and the proofing is set in English. None of that is wrong, but it makes a Hangul designer's first hour with the software feel slightly translated.

In **April 2025**, Kwon Gun‑oh (권건오) published **《폰트랩 타입 디자인》 (FontLab Type Design)** — the first Korean‑language guide to designing fonts, and specifically Hangul fonts, in FontLab. The book covers the toolset on FontLab's terms (glyph window, masters, mastering, components, OpenType features) and pairs each chapter with the practical methods Korean designers actually use: syllable‑block composition, jamo (자모) component reuse, the contextual logic that turns ㄱ + ㅏ + ㄴ into 간 the glyph rather than 간 the three‑letter string.

This matters more than it sounds. Korean has 11,172 modern Hangul syllables, and a Hangul font is mostly an exercise in component re‑use — the consonant ㄱ has to look right at the start of a syllable, in final position, beside a wide vowel and a narrow one. A font editor that hides components or makes them awkward is unusable; a guide in the wrong language doubles the cost of learning. A book by a Korean designer for Korean designers, published in Korean, is a small thing that quietly enlarges what FontLab is.

## Warhol's August 1962 silkscreen pivot

---
title: Warhol's August 1962 silkscreen pivot
slug: warhol-august-1962
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - history
  - print
summary: The month Warhol started screenprinting was the month repetition became a medium.
---

Andy Warhol began screenprinting in **August 1962**. His own explanation was characteristically dry: "I wanted something stronger that gave more of an assembly line effect." Within weeks of Marilyn Monroe's death he produced the **Marilyn Diptych** — fifty images of Monroe, all from a single 1953 Gene Kornman publicity still for *Niagara*, half in colour and half in fading black and white. The 1967 portfolio used Day‑Glo daylight‑fluorescent inks on ten 36 × 36‑inch screens in an edition of 250. *Shot Sage Blue Marilyn* sold at Christie's in May 2022 for **$195 million**.

What's worth holding on to from a typographic angle is that Warhol's silkscreen is a technology of *registration error*. Each colour is a separate pass, each pass slightly off, and the slip is the point. The eye reads four screens that don't quite line up as a face, and the misregistration becomes a kind of texture. Halftone newspapers had the same property accidentally. Warhol made it intentional.

Every Warhol image remains © Andy Warhol Foundation/ARS. Link to museum pages — the Tate's *Marilyn Diptych* page is the canonical reference — don't host.

## Sister Corita Kent, the silkscreen nun

Frances Elizabeth Kent (1918–1986) joined the Sisters of the Immaculate Heart of Mary in 1936. She learned silkscreen in 1951 from Maria Sodi de Ramos Martínez. In **1962** she took her students to the Ferus Gallery in Los Angeles to see Warhol's Campbell's Soup show, walked back to Immaculate Heart College, and started making prints that lifted the visual grammar of supermarket packaging into devotional art.

*the juiciest tomato of all* (1964) reads "Mary mother is the juiciest tomato of all." It is borrowing a Del Monte slogan to praise the Virgin. Cardinal James Francis McIntyre called the work "blasphemous"; she left the order in 1968. *Rainbow Swash* (1971) — six 150‑foot vertical bands of paint on a Boston natural‑gas tank — is sometimes described as "the largest copyrighted work of art in the world." Her **1985 USPS Love stamp** sold over 700 million copies.

The relevance to a font tool is that Kent treated typography as material. Words were cut, layered, screened, deliberately misaligned, set in a hand that wasn't quite trained — and the discipline came from the medium, not the curriculum. Anyone teaching variable‑font workflow today is in the same business: making letters do something the grid wasn't planning on.

## Money lace — guilloché, intaglio, and the Spirograph

---
title: Money lace — guilloché, intaglio, and the Spirograph
slug: guilloche-spirograph
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - history
  - print
summary: The fine‑line patterns on a banknote were a security feature before they were a design language. A British engineer made a toy of them in 1965.
---

Guilloché, from the French *guillocher* — to engrave with a rose engine. Peter Hubert Desvignes patented a "Speiragraph" in 1827, a geared lathe that drew the interlocking curves engravers had been cutting by hand for a century. The **Penny Black** (1840) used guilloché as its anti‑counterfeit. The US **Bureau of Engraving and Printing** was authorised in 1862, took over from American Bank Note Company in 1877, and has printed all US currency by **dry intaglio since 1968**.

> "In the 1970s, bank notes were decorated with guilloche patterns that can be easily reproduced with a Spirograph. These were not just beautiful details, but security features designed to make reproducing the notes extremely difficult." — Bank of Canada Museum

Which is the joke. **Denys Fisher** built the Spirograph from Meccano gears in 1962–65, debuted at the **1965 Nuremberg Toy Fair**, won UK Toy of the Year 1967, sold 30 million units by 1977. A child with a 50p toy could draw, in five minutes, the kind of curve that had previously been a defence against forgery. The pattern stayed on banknotes anyway because by then it had become the *look* of money — a security feature that was also a typographic convention.

For Vexy Lines this is the ancestral algorithm. Every parametric line tool — from a CSS animated SVG to a generative art piece — descends, eventually, from a French rose engine and a British toy.

## The hedcut at 45

summary: A stipple portrait newsroom called a "headline cut," drawn for the *Wall Street Journal* since 1979 and outlasting the editorial style around it.
---

"Hedcut" is newsroom shorthand for "headline cut." **Kevin Sprouls** introduced it to the *Wall Street Journal* in **1979** — a stipple portrait drawn from a photograph, light enough to sit beside text, distinctive enough that you knew which paper you were reading without looking at the masthead. **Noli Novak**, Croatian‑American, has drawn them since 1987 — photo, grayscale, contrast, print, trace on vellum, scan. Three to five hours each. The Smithsonian's National Portrait Gallery acquired **66 originals in 2002** when the *WSJ* downsized its New York office after September 11.

In **December 2019** the *WSJ* R&D team — Francesco Marconi, Eric Bolton, Cynthia Hua — trained a GAN on roughly 2,000 hedcuts to power a "draw your own" tool for members. Bolton's framing was careful: *"Artists will still draw the hedcuts for journalists and for celebrities… we are far from replacing the artist."* Five years on, that prediction looks accurate. The illustrators are still there, and the AI tool is a member toy.

The interesting craft question is why a hedcut still works at 45. The form is built for newsprint resolution and a four‑colour press neither of which exists in a 2026 reading experience. It still works because the dot pattern carries a *signal*: this person is a profile subject, this is a serious paper, this is a portrait that someone made. A photograph would be cheaper and worse.

## Seurat and the 220,000 dots

---
title: Seurat and the 220,000 dots
slug: seurat-220000-dots
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - history
  - art
summary: Pointillism is the proof that the eye does the painting.
---

Pointillism was developed in 1886 by **Georges Seurat** and **Paul Signac**, branching from Impressionism with a self‑consciously scientific argument. Seurat preferred his own term — *Divisionism* or *Chromo‑Luminarism* — but pointillism stuck. *A Sunday on La Grande Jatte — 1884* (1884–86) at the Art Institute of Chicago is **207.5 × 308.1 cm** and contains roughly **220,000 dots**.

The science behind it is almost older than the painting. **Michel Eugène Chevreul** published *De la loi du contraste simultané des couleurs* in 1839 — the foundational text on how adjacent colours change each other on the retina. **Ogden Rood**'s *Modern Chromatics* (1879) introduced the principle to a broader audience. Hermann von Helmholtz's optics underwrote it. Félix Fénéon's 1888 essay reads as a project brief written after the fact:

> "These colors, isolated on the canvas, recombine on the retina; we have, therefore, not a mixture of material colors (pigments), but a mixture of differently colored rays of light." — Félix Fénéon, 1888

The Smithsonian still employs scientific illustrators who draw stippled moth scales **0.0079 inches across**. The technique is unchanged because the optics it exploits are unchanged.

For a vector tool the moral is that *resolution is not the same as detail*. A million dots placed by an algorithm is not what Seurat did; what Seurat did is decide which dots, where, and what colour each contributes to its neighbours. The interesting bit is the rule, not the raster.

## Five centuries of line — Dürer, Hogarth, Bewick, Doré

---
title: Five centuries of line — Dürer, Hogarth, Bewick, Doré
slug: five-centuries-of-line
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - history
  - illustration
summary: Four printmakers, four techniques, the same problem — making a line do the work of a tone.
---

**Albrecht Dürer's *Knight, Death and the Devil* (1513).** Copperplate burin engraving, roughly 24.5 × 19.1 cm — one of his three *Meisterstiche*. Dürer himself called it simply "Der Reuter," the Rider. Every shadow is parallel hatching; every curved surface is cross‑hatching that turns with the form. There is no halftone here, only direction.

**William Hogarth's *A Rake's Progress* (1735).** Engravings published the day **the Engravers' Copyright Act 1734** ("Hogarth's Act") took effect — the first copyright law in any country to protect engravers, passed because pirates had flooded the market with knock‑offs of *A Harlot's Progress* three years earlier. Hogarth essentially co‑authored the law that made his next series possible.

**Thomas Bewick (1753–1828).** Revived wood engraving in Northumberland — end‑grain boxwood, white‑line technique, fine enough to compete with copper. *History of British Birds* (1797/1804) was the demonstration. The structural innovation was that his blocks could be **locked into letterpress alongside type** at the same height, which meant illustrated journalism became economically possible. The 19th‑century picture press is downstream of this one craftsman.

**Gustave Doré.** Dante's *Inferno*, 1861. Self‑published after no Paris house would risk the production cost. Sold out, kept selling, made him rich. The economy of horror in a Doré engraving is that nothing is rendered in tone — every shadow is a different *kind* of line, and the eye keeps interpreting them as the same darkness anyway.

For Vexy Lines this is the canon. Every modern hatching, stipple, or vector engraving algorithm is trying to reproduce something one of these four printmakers did with a tool small enough to hold.

## Drawing the invisible — contour lines and Minard

---
title: Drawing the invisible — contour lines and Minard
slug: contour-lines-minard
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - history
  - data
summary: An isobath, an isogon, an isotherm, and finally a march from Moscow drawn as a shrinking river.
---

**Pieter Bruinsz**, 1584 — the first known isobath, drawn for the Spaarne river near Haarlem. **Edmond Halley**, 1701 — the first published isogonic map, mapping magnetic declination across the Atlantic. **Alexander von Humboldt**, 1817 — the isotherm map that started a forty‑year "isoline craze" in 19th‑century cartography. Each was a quiet invention: a line that doesn't represent a coast or a road but a contour of a property of the world.

The endpoint of the genre is **Charles Joseph Minard's 1869 figurative map of Napoleon's Russian campaign of 1812**. Six variables on a single sheet — army size, geographic location in two dimensions, direction of travel, date, temperature on the retreat. The army leaves the Niemen at **422,000**, returns with **10,000**. The width of the band shrinks accordingly across the page, and the temperature graph below tracks the descent into −30°. Edward Tufte called it "the best statistical graphic ever drawn." Étienne‑Jules Marey, Minard's contemporary, called it "a defiance of the pen of the historian in its brutal eloquence."

The reason this matters in a vector tool conversation is that none of these images is *about* lines. They are about quantities that can only be drawn as lines. The tool is incidental to the idea. Once that's clear, contour mode in Vexy Lines stops being a stylistic option and starts being what cartography has been doing since 1584.

## From Spirograph to Fidenza

---
title: From Spirograph to Fidenza
slug: spirograph-to-fidenza
date: 2026-05-08
authors:
  - editorial
categories:
  - Vexy Lines
  - generative
  - history
summary: Lissajous, Blackburn, Fisher, Reas, Hoff, Hobbs — a one‑page genealogy of generative line.
---

Lissajous figures predate Lissajous: **Nathaniel Bowditch** drew them in 1815, **Jules Antoine Lissajous** worked out the optics in 1857. **Hugh Blackburn's harmonograph** (1844) was the first parametric drawing machine in a parlour. **Denys Fisher's Spirograph** (1965) was the first one for children. Then computers caught up.

**Casey Reas + Ben Fry** released **Processing** in 2001 from John Maeda's group at MIT — Golden Nica 2005, *de facto* lingua franca of generative art for a decade. **Anders Hoff** ("Inconvergent") and Argentina's **Manolo Naon** built styles inside that ecosystem you can still recognise at a glance — Hoff's stochastic line tangles, Naon's chunky pop‑colour grids.

The hinge year was **2021**. **Tyler Hobbs** released **Fidenza** on Art Blocks in June, an edition of 999 outputs from a single algorithm. By August, Starry Night Capital had spent roughly **$5 million** acquiring pieces. By May 2023 the floor sat above **60 ETH**. Hobbs coined the phrase **"long‑form generative art"** in May 2021 to describe the discipline of writing a program that produces *every* output good — not cherry‑picking a hundred from ten thousand runs.

The lesson for a tool like Vexy Lines is that the interesting part of a generative system is not the renderer. It's the constraint set. A Spirograph has two gears; a harmonograph has three pendulums; Fidenza has a flow field, a colour palette, and a curve sampler. The number of meaningful parameters is small — usually under a dozen. Everything else is taste.

**Jiyukobo** (字游工房) was founded in **September 1989** by three ex‑Sha‑Ken designers: **Torinoumi Osamu** (b. 1955), **Suzuki Tsutomu**, and **Katada Keiichi**. In 1990 they signed with Dainippon Screen for what became the **Hiragino** series. Torinoumi drew the kana for Hiragino Mincho — the part of a Japanese face where the personality lives — and the result has been the iPhone system Japanese font since 2007. The story passed around inside Apple at the time was that Steve Jobs's reaction was monosyllabic: "Cool!"

The fact a three‑person studio designs the type a hundred million people read every day on their phone is the kind of detail that changes how you think about scale. Hiragino is not an industrial product. It is the work of a small workshop that happens to be on the global hot path.

## A1 Mincho behind Makoto Shinkai's atmosphere

---
title: A1 Mincho behind Makoto Shinkai's atmosphere
slug: a1-mincho-shinkai
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - CJK
  - typography
summary: One of Morisawa's earliest typefaces, drawn before digital was clean and reissued because it wasn't.
---

**A1 Mincho** is one of Morisawa's earliest typefaces — old enough that the metal version had ink‑pool ridges at every stroke crossing where the wet ink pooled before drying. The Japanese term is **墨だまり (sumi‑damari)**, "ink pool." When Morisawa reissued A1 digitally, the choice was to *preserve* those ridges rather than scrub them out. The face is therefore a digital font that quietly remembers it used to be hot metal.

Makoto Shinkai's *Your Name* (君の名は, 2016) used A1 Mincho as the standard typeface in its marketing and subtitles, paired with **Shin Go**. The film is famous for treating light as a character; the type does the same job at smaller scale. The ridges where strokes meet catch the eye exactly the way a backlit cloud catches it, and the result is text that feels physical even on a digital projector.

The technical lesson is simple. A reissued metal face that fixes its imperfections becomes a different thing from the one designers actually used. Morisawa's bet on A1 was that the imperfections were the design.

## Tazugane Gothic, Monotype's first Japanese

---
title: Tazugane Gothic, Monotype's first Japanese typeface
slug: tazugane-gothic

authors:
  - editorial

  - CJK
  - typography
summary: The fix for the eternal road‑sign problem of Japanese set in Helvetica was to draw a Japanese typeface that matches Frutiger.
---

The structural problem with Japanese set alongside European sans is that the kanji are taller, the kana are shorter, and the Latin sits at the wrong vertical position relative to either. Sign painters and book designers have worked around it for half a century. Akira Kobayashi designed **Tazugane Gothic** (released 25 January 2017, with Kazuhiro Yamada and Ryota Doi) to fix the version of the problem that bothered him most: Japanese with Helvetica, on transit signage, looking visually broken.

The solution is precise. Tazugane is built as a partner for **Adrian Frutiger's Neue Frutiger 1450**. Frutiger glyphs are scaled to **108%** with the baseline shifted down, so Latin caps and kanji visually align without either feeling stretched. Ten weights, Ultra Light through Extra Black. Single weight $179, family $999 at launch.

The name is the surprise. **Tazugane** is an archaic Japanese word for *crane* (鶴 = symbol of longevity).

> "I had never heard of the archaic Japanese word for Tazugane but I immediately liked it as it reminded me of the grace and elegance of the crane." — Akira Kobayashi

**Monotype acquired Fontworks in 2023**, putting Tazugane and the Tsukushi family under one roof — most of the Japanese type Apple ships and most of what Monotype owns are now in the same building.

## Source Han Sans, the OpenType ceiling

---
title: Source Han Sans, the OpenType ceiling
slug: source-han-sans
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - CJK
  - OpenType
summary: Seven weights, four regional variants, 65,535 glyphs each — Adobe and Google's pan‑CJK Sans hits the per‑font ceiling on purpose.
---

**Released 15 July 2014.** Lead designer **Ryoko Nishizuka** at Adobe Tokyo. Project architect **Dr Ken Lunde**, who has spent three decades writing the books on CJK Unicode that everyone else cites. Foundry partners: **Iwata** (Japan), **Sandoll** (Korea — Joo‑Yeon Kang and Soo‑Young Jang), **Changzhou SinoType** (China). Latin/Greek/Cyrillic glyphs from Source Sans (Paul Hunt) **scaled to 115%** to match the CJK x‑height.

Seven weights × **65,535 glyphs each** — the OpenType per‑font ceiling. The total across weights and regional variants approaches **450,000 glyphs**. Four regional variants (SC / TC / Japan / Korea) are switched via the OpenType `locl` feature; the same Unicode codepoint resolves to a different glyph depending on the language tag. Latest version is 2.005, June 2025.

> "These fonts achieve the goal of 'No More Tofu,' meaning no empty glyphs when typesetting Unicode." — Geumho Seok, CEO of Sandoll

The cultural fact, which is harder to find in the documentation, is that the four foundries had to agree on weight curves, stroke proportions, and which radicals were drawn the same across regions and which weren't. There is no single "correct" form for many of these glyphs; the same Unicode point genuinely is a different character in a Tokyo paper and a Beijing one. Source Han is the negotiated result.

For a FontLab user the technical takeaway is the architecture of `locl`. Source Han's regional switching is the largest production deployment of language‑tagged glyph substitution that has ever shipped, and reading its sources is the fastest way to understand what the feature is actually for.

In **August 2015**, justfont's **金萱 (Jin Xuan)** hit NT$1.5 million in eighty minutes on the Taiwanese crowdfunding platform flyingV. Final tally: roughly **NT$26 million from 7,800 backers** — the most successful Taiwanese crowdfund of its time, and the first proof anyone had that East Asian display type could be funded the way Western indie type was funded.

The concept was a hybrid: 「明體的情感」+「黑體的簡潔」 — *the emotion of Mincho plus the simplicity of Hei*. It supports **Taiwanese‑Hokkien** Tâi‑lô romanisation and **indigenous Formosan** romanisations. Languages that historically had to be set in approximate Latin substitutes finally have a Hanzi face that matches.

The interesting design lesson is that you can't crowdfund a Latin family the way justfont crowdfunds a Hanzi family — the per‑backer cost of producing 13,000 glyphs is real, and a community willing to share it is rare. Taiwan happens to have one.

## Hangul — invented in 1443, lost, found in a coat

---
title: Hangul — invented in 1443, lost, found in a coat
slug: hangul-haerye
date: 2026-05-08
authors:
  - editorial
categories:
  - CJK
  - history
  - typography
summary: King Sejong invented the Korean alphabet in 1443. Its instruction manual was lost for four centuries, then carried through the Korean War in a man's coat.
---

King Sejong personally invented Hangul in **1443** — Sejong year 25, lunar 12月. Twenty‑eight letters: seventeen consonants drawn from the shape of the speech organs that produce them (ㄱ, ㄴ, ㅁ, ㅅ, ㅇ), and eleven vowels modelled on Heaven, Earth, and Human (ㆍ, ㅡ, ㅣ). It was promulgated in **1446** as **Hunminjeongeum** ("the proper sounds for the instruction of the people") with a separate explanatory volume — the **Haerye** — written by the Hall of Worthies scholars to argue, against literati objections, why the country needed an alphabet at all.

> "The speech of our country differs from that of China and does not link with the Chinese characters…" — Sejong, preface

The literati won the political fight for centuries; Hangul was treated as a script for women, children, and Buddhist texts. The Haerye was lost around the early 1500s. It was **rediscovered in 1940 in Andong** by **Jeon Hyeongpil (Gansong)**, who paid 10,000 won — the price of ten houses — instead of the 1,000 the seller asked, on the grounds that the manuscript was worth more. During the Korean War he carried it through evacuations **inside his coat**.

National Treasure No. 70 (1962). UNESCO Memory of the World, 1997.

For typography the importance is that Hangul is the only major writing system whose articulatory logic is documented by its inventor. You can read why ㄱ is shaped the way it is — it is a side view of the back of the tongue against the soft palate. No Latin letter has its design rationale on the record like that.

Founded **1984** by **Seok Geum‑ho** as 산돌타이포그라픽스 (Sandoll Typographics) — Korea's first proper independent type foundry. 1995 saw 산돌고딕 and 산돌명조, the foundational sans and serif of modern Korean digital type.

A free font is now the default voice of the Korean state interface, beside the Sandoll typeface that is the default voice of every Korean iPhone.

summary: Three names for the same style, and a 19th‑century Shanghai mission press at the centre of all of them.
---

The standard book serif of East Asian typography goes by three names. **Mingti** (明體) in Taiwan and Hong Kong. **Songti** (宋體) in mainland China. **Minchōtai** (明朝体) in Japan. The implication of the names is that the style descends from Ming or Song dynasty wood‑block carving.

It doesn't, exactly. The shape we now call Mincho descends much more directly from **19th‑century missionary lead type** — specifically Shanghai's **美華書館 (American Presbyterian Mission Press)** under **William Gamble** in the 1860s. The Qing scholar **錢大鏞** had already complained about it in *Ming Wen Zai*: *"Old books were written by skilled calligraphers… only in late Ming did engraving artisans create what was called Songti — vulgar and inferior."* He was the first person on record to make a typographic distinction between hand‑drawn and tool‑drawn calligraphic styles, four hundred years ago.

Mainland China and Hong Kong inherited the *Songti* name. Taiwan inherited *Mincho* via **Showa‑era Japanese phototype imports**, which arrived under their Japanese label and never had it removed. justfont's diplomatic conclusion is the right one:

> 「明體跟宋體都一樣，無論稱呼哪一個，意義是一樣的」 — "Mingti and Songti are the same — whichever name you use, the meaning is identical." — justfont

For a FontLab user designing a CJK serif the practical implication is that the *style* is fixed across three names, but the local conventions — preferred radical proportions, stroke contrast, where the brush memory shows — are not. Mincho draws differently in Tokyo and Taipei.

## Bézier vs de Casteljau — the Citroën curve nobody named

---
title: Bézier vs de Casteljau — the Citroën curve nobody named
slug: bezier-vs-de-casteljau
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - history
  - geometry
summary: Pierre Bézier got the curve named after him. Paul de Casteljau got there first and was made to sign an NDA.
---

**Pierre Bézier** worked at Renault and published in 1962. **Paul de Casteljau** worked at Citroën and got there in 1958–59. Citroën, on the grounds that the technique was a competitive advantage, **forbade publication** until 1985. Twenty‑seven years of silence later the science community had already named the curves after Bézier; the compromise was to name the *evaluation algorithm* after de Casteljau — which is why every renderer textbook says *Bézier curve, de Casteljau algorithm*. They mean the same thing. The names mark which company let its engineer publish.

For type design the consequence is the cubic/quadratic split that any FontLab user lives with daily:

- **PostScript / CFF / CFF2** — cubic Béziers (4 control points per segment)
- **TrueType** — quadratic Béziers (3 control points per segment)

Apple chose quadratic for TrueType in the late 1980s for one reason: the math was cheaper to render on an 8 MHz machine at 72 dpi. Adobe chose cubic earlier, on a faster baseline. **OpenType (1996)** finally let one font wrapper hold either flavour; on disk, every modern font is still one or the other. Conversion between them isn't lossless. A round trip from cubic to quadratic and back will, in general, change the curve.

The historical lesson is small but worth saying out loud. The geometry of every digital letter you read descends from a French car company that almost classified it.

## The open tool ecosystem

---
title: The open tool ecosystem
slug: open-tool-ecosystem
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - tools
  - open source
summary: HarfBuzz, FontTools, FontGoggles, Wakamai Fondue, fontdrop — the small set of open tools every type project leans on.
---

**HarfBuzz** — Persian حرف‌باز, "open type" with a secondary sense of "insincerely talkative" — is the shaping engine behind Chrome, Firefox, Android, GNOME, LibreOffice, Flutter, and Unreal Engine. **Behdad Esfahbod** began rewriting it in C++ in 2005; harfbuzz‑ng matured around 2012 with Mozilla's Jonathan Kew. Esfahbod won the 2013 O'Reilly Open Source Award. Most of the world's text passes through this library, and most of the people who pass text through it have never heard of it.

**FontTools / TTX** (Just van Rossum, 1999) is the Python library that lets you take any font apart, change one byte, and put it back together. Esfahbod revived the project around 2013 inside Google. At TypeCon 2014:

> "I'll make a bet — no matter what you use to create a font, if you round trip it through TTX, it will be functionally the same." — Behdad Esfahbod

**FontGoggles** (Just van Rossum, funded by Google Fonts) is a macOS preview tool — drag any `.ufo`, `.designspace`, or `.ttf` and it reloads as you save. Stephen Nixon: *"WOW. Font Goggles is just so good. It allows me to open a preview of the full Recursive designspace in maybe 4 or 5 seconds."*

**Wakamai Fondue** (Roel Nieskens, wakamaifondue.com) tells you what's inside any font dropped into the page — features, axes, glyph counts, languages. A major release in **April 2026** at Fontstand Berlin swapped the old Fontkit backend for **LibFont**.

**fontdrop.info** (Viktor Nübel) is the same idea with a stricter scope and a smaller payload — under 1.5 MB, all client‑side, born in 2016 from a German publishing‑house consulting job.

The right way to use these together is unromantic: HarfBuzz and FontTools are infrastructure; FontGoggles is a fast inner loop; Wakamai Fondue and fontdrop are diagnostics. A modern font workflow that doesn't lean on at least three of them is doing more work than it needs to.

- https://wakamaifondue.com/

**KABK Type & Media** (Den Haag). MA founded September 2002, roughly twelve students per year, head **Erik van Blokland**. Alumni include Andy Clymer, Antonio Cavedoni, Stephen Nixon, Frederik Berlaen — most of whom are now teaching the people who'll teach the next ones.

**Reading MATD** (University of Reading). Launched 1999. Programme director **Gerry Leonidas**. Field trips to **Plantin‑Moretus** in Antwerp and **Museum Meermanno** in The Hague. The late Gerard Unger taught six weeks a year for two decades.

## ClearType, TextKit 2, DirectWrite, ttfautohint

---
title: ClearType, TextKit 2, DirectWrite, ttfautohint
slug: cleartype-textkit-directwrite-ttfautohint
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - rendering
  - history
summary: The four pieces of screen‑rendering plumbing every font designer should know exists, even when they're not the one writing them.
---

**ClearType.** Announced by Bill Gates at COMDEX/Fall 1998 on **15 November 1998**: *"a major obstacle to ubiquitous on‑screen reading… overcome."* Subpixel anti‑aliasing exploited the fact that an LCD pixel is three coloured stripes; treat each stripe as an independent sample and you triple the horizontal resolution at the cost of slight colour fringing. Apple deprecated subpixel AA in macOS Mojave (2018) when display resolutions made the trade‑off no longer worth it. Core ClearType patents expired worldwide by **August 2019**.

**TextKit 2.** Introduced at **WWDC 2021** ("Meet TextKit 2," Donna Tom and Chris Willmore). The replacement for TextKit 1, which had been in OpenStep since the early 1990s. Already powering TextEdit and AppKit text fields since macOS Big Sur (2020). The architectural change is a switch from glyph‑run‑based layout to a paragraph‑graph model that is much friendlier to bidirectional and CJK text.

**DirectWrite.** The Windows text stack. Colour font support has shipped in stages: COLR in Windows 8.1, SVG/CBDT/sbix in the Windows 10 Anniversary Update (2016), full **COLRv1 paint‑tree** later. **DWriteCore** — part of Project Reunion / Windows App SDK — brings DirectWrite cross‑platform, and is what makes it possible to write a text application that renders identically on Windows and elsewhere.

**ttfautohint** (Werner Lemberg). The open‑source hinter that **Google Fonts adopted in 2012**. Supports 22 scripts; only adds hints along the y‑axis, which is a deliberately narrow scope — most of what hinting actually does is align horizontal stems to pixel boundaries.

The reason a type designer should know these names even when not writing them is that fonts behave differently in each. A face that hints itself elegantly on Windows DirectWrite renders unhinted on macOS TextKit 2 — Apple's renderer has ignored TrueType hints since OS X. Designing for both means designing without trusting either.

## GSUB, GPOS, and HarfBuzz

---
title: GSUB, GPOS, and HarfBuzz
slug: gsub-gpos-harfbuzz
date: 2026-05-08
authors:
  - editorial
categories:
  - FontLab 8
  - OpenType
  - rendering
summary: Two OpenType tables and one shaping engine carry every line of text you read.
---

**GSUB** substitutes glyphs. `f i` becomes `fi`. `1/2` becomes ½. An Arabic isolated form becomes a medial form depending on what's beside it. **GPOS** positions them — kerning, mark attachment, cursive connection. Both share the same architectural layout: ScriptList → FeatureList → LookupList. The script identifies the writing system, the feature is the named behaviour the application asked for (`liga`, `kern`, `mark`), the lookup is the actual rule.

**HarfBuzz** — Persian حرف‌باز, "open type" — is the shaping engine that walks those tables and produces the run of positioned glyphs an application then draws. It is what Chrome, Firefox, Android, GNOME, LibreOffice, Flutter, and Unreal Engine all use. **Behdad Esfahbod** began rewriting it in C++ in 2005 from an earlier C codebase; harfbuzz‑ng stabilised around 2012 with Mozilla's Jonathan Kew. The interesting thing is the proportion: most of the world's user‑facing text software in 2026 ends up at HarfBuzz. **Simon Cozens'** *Fonts and Layout for Global Scripts* is the readable book on what the library is doing under the hood.

For variable fonts there's one extra wrinkle worth knowing. The **FeatureVariations** mechanism lets a font apply a different lookup at different points in the design space — a low‑contrast shape at light weights, a high‑contrast shape at black, with the substitution happening *as part of shaping*, not as a separate styling step. It's the correct way to encode the kind of "the design does something different at the extremes" behaviour designers used to fake with separate styles.

The pragmatic point for a FontLab user is that GSUB/GPOS errors live at the rendering boundary, not at the editing one. A feature that looks correct in the editor may shape wrong in HarfBuzz, and the only honest test is to render through the same shaper Chrome will. `hb-shape` on the command line is the small tool that solves an enormous category of bugs.

- https://learn.microsoft.com/en-us/typography/opentype/spec/gsub
- https://harfbuzz.github.io/why-do-i-need-a-shaping-engine.html
- https://simoncozens.github.io/fonts-and-layout/features.html
