# Chapter 9 — Plugin & Extension Stack

## Design principle

Every plugin in the stack must earn its place with a concrete use case in this blog. No plugins added speculatively. No plugins added because they were useful in a different site. If a plugin's feature can be achieved with a Markdown extension or plain HTML, the plugin is not added.

## Plugin list

Declared in `mkdocs/mkdocs.yml` under `plugins:`, in this order:

```yaml
plugins:
  - search
  - materialx/tags
  - materialx/blog:
      # ... (full config in chapter 7)
  - awesome-nav
  - include-markdown:
      opening_tag: "{!"
      closing_tag: "!}"
  - llmstxt:
      enabled: true
  - copy-to-llm:
      enabled: true
  - vexy-output-as-input:
      enabled: true
  - vexy-strip-number-prefix:
      enabled: true
  - vexy-tags:
      enabled: true
```

Order matters: plugins run in declaration order during the build event pipeline. `search` and the blog/tags plugins run early (they index content). Navigation plugins (`awesome-nav`) run after content is collected. Output plugins (`llmstxt`, `copy-to-llm`) run last, after HTML is generated.

## Plugin-by-plugin rationale

### `search` (properdocs built-in)
Client-side full-text search. Required. No configuration needed beyond declaration. Integrates with the Web Component's search loupe via the `search-from` attribute routing queries to `https://search.fontlab.com/`.

### `materialx/tags` (materialx package)
Generates `/tags/` index from `tags:` front-matter fields. Looser than categories — no allowed-list enforcement. Used for fine-grained topic indexing (e.g. `COLRv1`, `kerning`, `Python scripting`). Complements categories (coarse) with tags (fine).

**Version pin:** ships with `mkdocs-materialx>=10.1.4`

### `materialx/blog` (materialx package)
The load-bearing plugin. See [chapter 7](07.md) for full configuration. Generates: paginated index, archive, category pages, author profiles, reading-time estimates.

**Version pin:** ships with `mkdocs-materialx>=10.1.4`

### `awesome-nav` (`mkdocs-awesome-nav`)
Replaces the default MkDocs nav with directory-based `_nav.yml` files. Eliminates the need to list every page in `mkdocs.yml`'s `nav:` key. For a blog, the only manually-listed pages are the handful of non-blog pages (`index.md`, `about.md`); posts are handled by the blog plugin. `awesome-nav` is still useful for future non-blog sections.

**Version pin:** `mkdocs-awesome-nav>=2.9.0`

### `include-markdown` (`mkdocs-include-markdown-plugin`)
Allows one Markdown file to include another. Useful for the `/about/` page (which may share a short bio block with the author profile), and for any future reference pages that reuse content fragments. Custom tags `{!` / `!}` avoid collision with other template syntaxes.

**Version pin:** `mkdocs-include-markdown-plugin>=7.0.0`

### `llmstxt` (`mkdocs-llmstxt`)
Generates `llms.txt` and `llms-full.txt` at the site root, following the emerging [llms.txt convention](https://llmstxt.org/). These files let LLMs discover and summarise the site's content without crawling. Low-effort; high future value for a technical blog.

**Version pin:** `mkdocs-llmstxt>=0.2.0`

### `copy-to-llm` (`mkdocs-copy-to-llm`)
Adds a "Copy for LLM" button to each page, generating a clean Markdown representation of the page content. Useful for technical posts where readers may want to paste content into an LLM context. Complements `llmstxt`.

**Version pin:** `mkdocs-copy-to-llm>=0.1.0`

### `vexy-output-as-input` (vexy-mkdocs-output-as-input)
Allows the build to treat generated pages (e.g. the blog index) as additional input for further processing. Enables post-processing passes that need access to the full rendered output. Used for custom sitemap generation and link verification.

**Version pin:** `vexy-mkdocs-output-as-input>=0.1.0`

### `vexy-strip-number-prefix` (vexy-mkdocs-strip-number-prefix)
Strips numeric prefixes from filenames (e.g. `01-introduction.md` → `/introduction/`). Allows authors to use numbered filenames for editor ordering without those numbers appearing in URLs.

**Version pin:** `vexy-mkdocs-strip-number-prefix>=0.1.0`

### `vexy-tags` (vexy-mkdocs-tags)
Extended tags functionality on top of `materialx/tags`. Adds tag cloud rendering, tag frequency metadata, and cross-references between tags. Works alongside, not instead of, `materialx/tags`.

**Version pin:** `vexy-mkdocs-tags>=0.1.0`

## Markdown extensions

Declared in `mkdocs.yml` under `markdown_extensions:`:

```yaml
markdown_extensions:
  - pymdownx.highlight:
      anchor_linenums: true
      line_spans: __span
      pygments_lang_class: true
  - pymdownx.inlinehilite
  - pymdownx.superfences:
      custom_fences:
        - name: mermaid
          class: mermaid
          format: !!python/name:pymdownx.superfences.fence_code_format
  - pymdownx.tabbed:
      alternate_style: true
  - pymdownx.tasklist:
      custom_checkbox: true
  - pymdownx.emoji:
      emoji_index: !!python/name:material.extensions.emoji.twemoji
      emoji_generator: !!python/name:material.extensions.emoji.to_svg
  - pymdownx.tilde
  - pymdownx.caret
  - pymdownx.mark
  - pymdownx.keys
  - pymdownx.details
  - pymdownx.snippets
  - admonition
  - attr_list
  - def_list
  - footnotes
  - md_in_html
  - tables
  - toc:
      permalink: true
      toc_depth: 3
  - vexy_python_markdown_steroids.all
```

The `vexy_python_markdown_steroids.all` shorthand registers all extensions from the `vexy-python-markdown-steroids` package — custom admonitions, enhanced figure handling, and typographic improvements specific to the FontLab house style.

## Known interactions

| Interaction | Resolution |
|-------------|-----------|
| `materialx/tags` + `vexy-tags` | `materialx/tags` runs first (declaration order); `vexy-tags` reads its output |
| `materialx/blog` + `awesome-nav` | Blog posts are excluded from `awesome-nav`'s nav construction; the blog plugin owns those URLs |
| `include-markdown` + `materialx/blog` | Includes are resolved before the blog plugin indexes content — correct order |
| `llmstxt` + `copy-to-llm` | Independent; no interaction |
