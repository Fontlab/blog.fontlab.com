# Chapter 6 — Site Structure & Navigation

## URL map

```
https://blog.fontlab.com/
│
├── /                           Home — brief landing, links to blog
├── /about/                     About page — who writes here, what it's for
│
└── /blog/                      Blog index (paginated, newest first)
    ├── /blog/archive/          Year-based archive index
    │   ├── /blog/archive/2013/
    │   ├── /blog/archive/2024/
    │   └── ...
    ├── /blog/category/         Category index
    │   ├── /blog/category/typography/
    │   ├── /blog/category/opentype/
    │   ├── /blog/category/variable-fonts/
    │   ├── /blog/category/colour-fonts/
    │   └── /blog/category/fontlab/
    └── /blog/author/           Author profiles
        └── /blog/author/adam/
```

Post URLs follow the pattern: `/blog/{yyyy}/{mm}/{dd}/{slug}/`

The archive, category, and author routes are generated automatically by the MaterialX blog plugin. No manual nav configuration is needed for those routes.

## Pages that require source files

| URL | Source file | Notes |
|-----|------------|-------|
| `/` | `src_docs/md/index.md` | Landing page; can redirect to `/blog/` or show a brief intro |
| `/about/` | `src_docs/md/about.md` | Condensed from `oldpub/about/index.html` |
| `/blog/` | `src_docs/md/blog/index.md` | Plugin overrides this page; keep the file minimal |

## Navigation structure

The local menu is configured via the Web Component config object (see [chapter 8](08.md)). The top-level items are:

```javascript
localMenu: [
  { label: "Blog",    url: "/blog/" },
  { label: "Archive", url: "/blog/archive/" },
  { label: "About",   url: "/about/" },
]
```

The MaterialX theme's sidebar navigation is not used — the blog plugin generates its own index pages, and the site is shallow enough that a sidebar would be noise. The `nav` key in `mkdocs.yml` is set to include only the top-level pages; blog posts are excluded from the nav and discovered by the plugin from `src_docs/md/blog/posts/`.

## Home page

The home page is not a blog post. It is a plain Markdown page that serves as a brief landing. Two acceptable approaches:

**Option A — Immediate redirect.** The `index.md` front-matter includes a redirect to `/blog/`:

```yaml
---
template: redirect.html
redirect: /blog/
---
```

This is clean but requires a redirect template in `mkdocs/mk-fontlab/redirect.html`.

**Option B — Brief landing.** A short page (3–5 sentences) describing what the blog is, with a prominent "Read the blog" link. No hero image, no animation.

Decision deferred to implementation; Option B is preferred because it gives search engines something to index at the root URL.

## About page

Condensed from `reference/fontlab-com-oldpub/about/index.html`. The about page answers:

- What is this blog?
- Who writes here?
- How do I contact FontLab?

It is not a full company profile — that lives on fontlab.com. It is not a team directory — it is one short page. Target: under 300 words.

## Categories

Initial category set:

| Category | Slug | Use for |
|----------|------|---------|
| Typography | `typography` | Type design craft, historical pieces |
| OpenType | `opentype` | OT spec deep-dives, GSUB/GPOS explainers |
| Variable Fonts | `variable-fonts` | Axes, designspace, masters |
| Colour Fonts | `colour-fonts` | COLR, SBIX, SVG, COLRv1 |
| FontLab | `fontlab` | FontLab-specific workflows |

Posts may carry more than one category. Category pages are auto-generated by the plugin.

## What is deliberately absent

**No sidebar.** The site is a blog, not a documentation tree. Sidebar navigation implies depth; this site is deliberately shallow.

**No tags page in the main nav.** Tags are configured in the plugin and accessible via the MaterialX tags index, but there is no top-level nav link to `/tags/`. Tags are a discovery mechanism, not primary navigation.

**No search results page in the nav.** Search is in the Web Component menu — the loupe icon. Results appear in-place. No dedicated search page.

**No pagination controls in the nav.** The blog plugin handles pagination internally. Older posts are reachable via the archive.
