# Chapter 8 — Theme & Chrome

## The fundamental rule

No Node.js. No npm. No PostCSS. No Tailwind build step. CSS is plain CSS with custom properties. JS is the Web Component, loaded from the FontLab CDN. If a styling goal requires a build tool, the goal is reconsidered.

## MaterialX header suppression

The MaterialX theme renders a `<header class="md-header">` at the top of every page. We do not use it — the FontLab Web Component provides navigation. The header is hidden with a single CSS rule in `mkdocs/mk-fontlab/fontlab-chrome.css`:

```css
.md-header {
  display: none !important;
}
```

This file is referenced from `mkdocs.yml` as an extra CSS file:

```yaml
extra_css:
  - assets/css/fontlab-chrome.css
```

The `!important` is intentional and non-negotiable here: MaterialX sets `position: sticky` on this element with high specificity, and we want it completely gone, not just hidden behind content.

## Template override

`mkdocs/mk-fontlab/main.html` extends the MaterialX base template. It injects the Web Component script and custom elements into every page:

```html
{% extends "base.html" %}

{% block extrahead %}
  {{ super() }}
  <script defer src="https://i.fontlab.com/menu/fontlab.js"></script>
{% endblock %}

{% block header %}
  <fontlab-menu
    mode="dark"
    site-label="Blog"
    site-url="https://blog.fontlab.com/"
    search
    search-from="blog"
  ></fontlab-menu>
{% endblock %}

{% block footer %}
  <fontlab-footer mode="dark"></fontlab-footer>
  <script>
    document.addEventListener('DOMContentLoaded', function () {
      var menuEl = document.querySelector('fontlab-menu');
      if (menuEl) {
        menuEl.config = {
          localMenu: [
            { label: 'Blog',    url: '/blog/' },
            { label: 'Archive', url: '/blog/archive/' },
            { label: 'About',   url: '/about/' },
          ],
          search: { from: 'blog' },
        };
      }
    });
  </script>
{% endblock %}
```

The `defer` attribute on the script tag means the component registers after the DOM is parsed. The `DOMContentLoaded` listener for the config assignment fires after that, so the sequence is safe.

## Web Component attributes vs config object

`<fontlab-menu>` accepts both HTML attributes (for scalar values) and a JS config object (for complex structures). Both are used:

| Surface | Used for |
|---------|----------|
| HTML attributes | `mode`, `site-label`, `site-url`, `search`, `search-from` |
| `el.config = {...}` | `localMenu` array, nested search config |

Attributes take precedence over config object when both specify the same field. The local nav items — Blog, Archive, About — are not expressible as scalar attributes, so they go in the config object.

## CSS custom properties

The site's colour tokens and spacing values live in `src_docs/md/assets/css/extra.css`, referenced from `mkdocs.yml` as an additional CSS file:

```css
:root {
  --fl-bg: #1a1a2e;
  --fl-fg: #e8e8f0;
  --fl-accent: #7b68ee;
  --fl-code-bg: #12121e;
  --fl-border: #2e2e4e;
}

/* Adjust MaterialX content area to account for hidden header */
.md-main {
  padding-top: 0;
}

/* Code blocks */
.highlight pre {
  background: var(--fl-code-bg);
  border: 1px solid var(--fl-border);
  border-radius: 4px;
}
```

Actual colour values to be confirmed against the FontLab brand guide before v0.1.0 ships. The token names are fixed; the values are adjustable without touching markup.

## Typography

Work Sans is used for UI elements in the Web Component — the component loads it into `document.head` on first use, with a guard flag to prevent duplicate injection. The blog post body uses MaterialX's default type scale (Source Serif, or the MaterialX successor font stack). No additional font loading in the blog's own code.

Inline code and code blocks use a monospace stack. MaterialX ships `JetBrains Mono` by default; we keep it.

## Dark mode only

The blog ships dark mode only. `mode="dark"` is set on both `<fontlab-menu>` and `<fontlab-footer>`. The MaterialX theme's built-in light/dark toggle is disabled by setting:

```yaml
theme:
  name: materialx
  palette:
    scheme: slate   # MaterialX dark scheme
```

No `toggle` block. No `prefers-color-scheme` media query override. If a user wants light mode they can use their OS reader view. This decision simplifies the CSS significantly — no dual-mode token set to maintain.

## What does not exist in this layer

- No custom JavaScript for analytics (use a separate consent-respecting solution if ever needed, not a theme override)
- No cookie banner (no tracking cookies; no banner needed)
- No custom 404 page (GitHub Pages default is acceptable for v0.1.0; this is a later roadmap item)
- No print stylesheet (out of scope)
