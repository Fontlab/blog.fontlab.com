## Key ownership rules

**`src_docs/md/` is the only directory authors touch.** Everything else is infrastructure. A new post means a new file in `src_docs/md/blog/posts/`. That is all.

**`docs/` is build output.** It is committed to `main` only for the CNAME and `.nojekyll` sentinel files. The rest is generated by the build. The CI deploy workflow writes the full built site to the `gh-pages` branch; `docs/` on `main` does not need to match.

**`mkdocs/mkdocs.yml` is the single source of truth for site config.** The ProperDocs `docs_dir` points to `src_docs/md`. The `site_dir` points to `docs`. No other config file controls what gets built.

**`reference/` is read-only input.** Nothing in `reference/` is imported by the build. It exists for humans to read during content porting. It is not installed as a Python package and is not referenced by `mkdocs.yml`.

## What `docs_dir` contains

`src_docs/md/` is the ProperDocs `docs_dir`. This means:

- Markdown files become pages
- Assets (images, CSS, JS) placed here are copied verbatim to the build output
- Subdirectories become URL path segments (except `blog/posts/` — the blog plugin controls those URLs)
- `blog/.authors.yml` is consumed by the MaterialX blog plugin at build time

## Naming conventions

- Post filenames: `YYYY-slug.md` (year prefix helps with ordering in editors; the plugin uses the front-matter `date.created` for actual URL routing)
- Image files: kebab-case, no spaces, no uppercase. Placed in `src_docs/md/blog/posts/img/` or `src_docs/md/assets/img/`
- CSS overrides: `src_docs/md/assets/css/extra.css` (referenced from `mkdocs.yml` as `extra_css`)
