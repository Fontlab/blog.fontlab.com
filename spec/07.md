# Chapter 7 — MaterialX Blog Plugin Configuration

## Plugin declaration

In `mkdocs/mkdocs.yml`:

```yaml
plugins:
  - search
  - materialx/tags
  - materialx/blog:
      blog_dir: blog
      post_dir: "{blog}/posts"
      post_date_format: full
      post_url_date_format: yyyy/MM/dd
      post_url_format: "{date}/{slug}"
      post_slugify: !!python/object/apply:pymdownx.slugs.slugify
        kwds:
          case: lower
      post_slugify_separator: "-"
      post_excerpt: required
      post_excerpt_max_authors: 1
      post_excerpt_max_categories: 3
      post_readtime: true
      post_readtime_words_per_minute: 200
      authors: true
      authors_file: "{blog}/.authors.yml"
      categories: true
      categories_slugify: !!python/object/apply:pymdownx.slugs.slugify
        kwds:
          case: lower
      categories_slugify_separator: "-"
      categories_allowed:
        - Typography
        - OpenType
        - Variable Fonts
        - Colour Fonts
        - FontLab
      archive: true
      archive_name: Archive
      archive_date_format: yyyy
      archive_url_date_format: yyyy
      archive_url_format: "archive/{date}"
      pagination: true
      pagination_per_page: 10
      pagination_url_format: "page/{page}"
      draft: false
      draft_on_serve: true
      draft_if_future_date: true
```

## Front-matter contract

Every post must include these fields. The build will fail if `authors`, `categories`, or `date.created` are missing.

```yaml
---
authors:
  - adam                          # must match a key in .authors.yml
categories:
  - Typography                    # must be in categories_allowed list
date:
  created: 2024-01-15             # ISO 8601 date; controls URL and archive placement
  updated: 2024-01-20             # optional; shown in post metadata if present
draft: false                      # true = excluded from production build; visible on serve
pin: false                        # true = pinned to top of index (use sparingly)
slug: colour-fonts-in-opentype    # optional; derived from filename if absent
---

Post excerpt visible on the index page goes here, before the more marker.

<!-- more -->

Rest of the post content follows.
```

The `<!-- more -->` separator is **required** (`post_excerpt: required`). The build fails without it. This is intentional: it forces authors to write a deliberate excerpt rather than letting the plugin guess.

## .authors.yml schema

Located at `src_docs/md/blog/.authors.yml`:

```yaml
authors:
  adam:
    name: Adam Twardoch
    description: FontLab co-founder, type tools developer
    avatar: https://i.fontlab.com/assets/authors/adam.jpg
    url: https://twardoch.github.io/
```

Fields:
- `name` — display name, shown on post metadata and author profile page
- `description` — one-line bio, shown on author profile page
- `avatar` — URL to square image (80×80px minimum); hosted on `i.fontlab.com` CDN
- `url` — author's external link (optional but recommended)

Adding a new author: add an entry here, then use the key in post front-matter `authors` list.

## Post URL format

The configured `post_url_format: "{date}/{slug}"` combined with `post_url_date_format: yyyy/MM/dd` produces URLs like:

```
/blog/2013/09/23/colour-fonts-in-opentype/
/blog/2024/01/15/variable-font-axes-explained/
```

The date in the URL comes from `date.created` in front-matter — not from the filename, not from git history. This allows porting old posts with their original publication dates preserved exactly.

## Draft handling

| Setting | Behaviour |
|---------|-----------|
| `draft: true` | Excluded from `./build.sh build` output |
| `draft: true` + `./build.sh serve` | Visible locally (draft_on_serve: true) |
| `draft_if_future_date: true` | Posts with a future `date.created` auto-treated as drafts |
| `draft: false` (or absent) | Included in all builds |

Draft posts are not merely hidden — they are excluded from the paginated index, archive, category pages, and sitemap. Setting `draft: false` on a post is the commit that makes it live.

## Pagination

Ten posts per index page. Page 1 is `/blog/`, subsequent pages are `/blog/page/2/`, etc. The plugin generates previous/next controls automatically using MaterialX pagination components.

## Archive

Year-level archive only. The archive index at `/blog/archive/` lists all years. Each year page (`/blog/archive/2013/`) lists all posts from that year, most recent first.

## Categories

Strictly enforced via `categories_allowed`. A post with an unlisted category name causes the build to fail. This prevents typos (`colour-fonts` vs `Colour Fonts`) from creating orphan category pages. The allowed list is the canonical set; add new categories by editing `mkdocs.yml` and opening a PR.

## Tags

Tags are handled by the separate `materialx/tags` plugin (see [chapter 9](09.md)). Tags are looser than categories — no allowed-list enforcement. They appear on post pages and generate a `/tags/` index, but are not in the primary navigation.
